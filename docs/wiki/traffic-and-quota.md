# 流量与配额

Meridian 统计客户端与代理之间的有效请求、响应载荷。仪表盘、站点配额、趋势与 Telegram 报告使用统一计费口径。

## 计费方向

在“全局设置 → 系统设置”选择：

| 方式 | 计入内容 |
| --- | --- |
| 双向（默认） | 客户端上传至代理的载荷 + 代理返回客户端的载荷。 |
| 单向 | 只计算代理返回客户端的载荷。 |

例如下载 500 MB 视频、上传少量播放进度信息，双向统计约为 500 MB 加实际上传载荷。不会因为服务器先回源再转发，就把同一段下载载荷计算两遍。

它不是服务器网卡总流量，也不包含操作系统或其他服务的流量；与云厂商统计的 TCP / TLS 开销和计费规则可能不同。

## 流量周期与时区

全局设置支持每月 `1–31` 日重置，或选择“不重置（累计流量）”。

- 默认每月 1 日，按服务进程的本地时区（通常由部署环境的 `TZ` 设置）计算流量周期。
- 短月将不存在的日期按当月最后一天处理，例如 31 日在二月按月底处理。
- 周期变化影响当期用量与配额视图，不会把累计流量简单当作当月用量。
- 全局设置中的显示/通知时区用于界面和定时通知；流量计费沿用服务进程本地时区。第一阶段卡片的“下次重置”显示服务器计算的准确时刻，并转换为浏览器时区。

修改计费方向、周期或时区后，核对站点额度和当前周期，避免把不同口径的数值直接比较。

## 站点流量额度

在“站点编辑 → 高级策略”填写额度：

```text
0：不限
1000：1000 GB
```

界面按 `1 GB = 1024³` 字节换算。达到额度后，新的代理请求会被拒绝，并可能截断继续超过额度的传输；日志可出现 `403` 与 `traffic quota exceeded`。

恢复访问时，检查当期用量、重置周期或调整额度。不要把配额错误误判为 Emby 用户密码错误。

## 单连接限速

单位是 **Mbps**，`0` 为不限。它限制单个代理连接，而不是所有客户端共享的一条总带宽预算。

例如设置 `8 Mbps`，理论上约 `1 MB/s`；实际速度还取决于上游、网络、客户端和其他开销。多连接客户端的总速度可能高于单连接值。

第一阶段测试版的配额卡片使用当前周期用量计算百分比及剩余额度，累计用量单独展示。配额可运行中修改，收紧到已用额度以下会阻止继续超额传输，可能中断播放。

## 站点总下载限速（第一阶段测试版）

站点内所有代理连接共享上限，单位 Mbps，0 为不限。总限速和单连接限速同时生效，实际受较低的可用速率约束；修改总限速立即影响正在进行的下载，修改单连接限速仅作用于新请求。

HTTP、缓存命中、动态代理及 WebSocket 下载都参与总预算，上传不受下载限速影响。限速允许最多约 32 KiB 的短时突发；不提供各客户端之间的公平带宽保证。JSON 导入导出保留 `total_speed_limit`，CSV 仍只用于基本字段和账号迁移。

## 直连模式

直连媒体从客户端直接访问媒体源，不通过 Meridian。

| 请求 | Meridian 统计、配额与限速 |
| --- | --- |
| 仍经代理的登录、海报、字幕与 API | 适用。 |
| 已直连的视频、清单与分片 | 不适用。 |

所以直连后服务器媒体带宽下降、面板流量明显减少属于预期行为。需要控制媒体总用量时，应选择代理播放，或由真正承载媒体的上游控制。

## 查看趋势

仪表盘提供平滑的趋势展示；流量统计页查看站点与时间范围。曲线只是展示方式，实际统计仍来自采集样本。

出现差异时，先确认计费方向、时间范围、时区和播放模式，再查看 [请求日志](logs-and-diagnostics.md)。
