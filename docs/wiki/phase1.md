# 第一阶段开发说明

本轮完善现有单管理员、单节点模式。正式版本仍为 v1.14.2；多用户、多节点和 Cloudflare Workers 部署尚未实现。

## 可体验的改进

1. 站点卡片显示本周期流量、剩余额度、下次重置、累计流量和计费方向。周期继续使用 v1.14.2 的服务进程本地时区，修正旧界面将它归于面板显示/通知时区的错误说明。
2. 改名、配额和限速使用运行中更新。路由与代理策略修改仍会重启站点，保存前提示影响。
3. “站点总下载限速”让多条连接共享下载预算，允许约 32 KiB 短时突发，不保证客户端间公平分配。修改总限速影响现有下载；单连接限速仅影响新请求。上传、直连或跳转到外部上游的媒体不参与该下载限制。
4. 复制草稿、保存配置模板、批量启停/配额/限速。模板只保存策略，不含回源、入口、账号、请求头和动态域名规则，随整机备份保存，站点 JSON/CSV 导出不含模板。批量操作每次支持 1–500 个站点，先预览、再确认、逐项反馈，失败不会撤销其他成功项。
5. 正式版更新与配套回滚。移除测试更新通道，普通用户只接收正式 Release。

## 正式版更新与回滚

面板和安装器只安装正式版本，不提供通道选择或测试 Release。开发提交不会创建正式 Release，也不会进入普通用户更新入口。

支持该功能的标准 systemd 安装可使用：

```bash
sudo bash install.sh update
sudo bash install.sh rollback
```

v1.14.2 的旧更新代理可继续执行正式版更新；显式恢复快照才需要新版代理及配套安装器。不要在尚未发布时拿主支旧安装器替换开发版组件。

回滚将程序、数据目录和服务文件一起恢复到上次升级前。升级后的配置、账号及流量记录会被旧快照替换，操作前会另存当前数据，失败时尝试恢复操作前状态。外部证书、Nginx 配置不在该快照中；数据库必须实际位于数据目录内，不支持符号链接路径。不支持的数据库布局会在更新停服前报错。Docker 采用固定镜像标签与人工数据备份恢复。

成功回滚后快照移入 `rollback-restored-*` 归档，不再作为可重复点击的回滚点；再次恢复需使用归档人工处理。它不是任意版本切换器或多级撤销功能。

`beta` 仅保留为集中开发分支。其带提交号的 CI 程序用于独立环境验证，不属于用户更新通道。演示站 `/test/` 展示开发进度，正式入口仍对应正式版本。

## 验证建议

使用独立数据目录及虚构上游，检查多条下载共享限速、修改配置时的连接表现、模板与批量操作。账号备忘录只存储信息，不向上游验证密码或自动模拟播放。
